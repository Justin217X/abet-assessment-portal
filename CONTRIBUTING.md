# Contributing Guidelines

## Workflow

1. Create or select a GitHub issue for your task.
2. Create a branch based on `main`.
3. Make your changes and commit them.
4. Push your branch to GitHub.
5. Open a pull request.
6. Have another team member review the changes.
7. Merge the pull request when approved.

## Branch Naming

Use descriptive branch names:

- `feature/` for new functionality
- `fix/` for bug fixes
- `test/` for tests

Examples:
- `feature/canvas-api`
- `fix/login-validation`

## Commit Messages

Write short messages explaining the change.

Examples:
- `Add initial API route structure`
- `Update database design documentation`
- `Fix report validation issue`

## Pull Requests

Each pull request should explain:
- What changed
- Why the change was made
- How the change was tested, if applicable

At least one teammate should review changes before merging into `main`.

## Security

Do not commit passwords, API tokens, credentials, environment files containing secrets, or real student data.
